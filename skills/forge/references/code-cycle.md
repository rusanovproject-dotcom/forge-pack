# Трек A — Code cycle (Superpowers + Compound)

> Детерминированный путь написания/правки кода одной головой (main loop). Запускается, когда
> Шаг 0 forge дал вес «одна голова». Два плагина НЕ дублируются: **Compound** = план и ревью,
> **Superpowers** = процесс (исполнение, TDD, дебаг, верификация). Зови только нужное.

## Фазы (0–6)

> Полный конвейер — семь фаз. Ниже детализированы 1–5 (план→верификация). Обрамляют их два
> шага, описанные в `SKILL.md`, не повторяю целиком: **Фаза 0 — Recon стека** (как тут гоняются
> тесты/линт/билд; без неё TDD-«падающий тест» пустой) и **Фаза 6 — Land** (ветка → коммит →
> Draft PR → аппрув перед main). И помни деление **лёгкий путь / полный путь** (см. `SKILL.md`
> Шаг 0): лёгкий пропускает Фазы 1–2 (план/исполнение) — не гони ce-plan на обозримую фичу.

### Фаза 1 — План (Compound) · только полный путь
- Задача размытая → `/compound-engineering:ce-brainstorm` (диалог: что строим, зачем, варианты).
- Задача ясная → `/compound-engineering:ce-plan` (декомпозиция, критичные файлы, развилки).
- План важный/крупный → `/compound-engineering:document-review` ПЕРЕД кодом
  (персоны: coherence · feasibility · scope-guardian · security-lens · product-lens).

### Фаза 2 — Исполнение (Superpowers)
- `/superpowers:executing-plans` — ведёт план с чекпоинтами ревью по ходу.

### Фаза 3 — Код через TDD (Superpowers)
- `/superpowers:test-driven-development` — сначала падающий тест, потом код.
  Без исключений для фич и багфиксов. Это рельсы, не срезай.

### Фаза 4 — Дебаг (Superpowers)
- Любой баг / упавший тест → `/superpowers:systematic-debugging` (гипотеза → проверка → вывод)
  ДО того, как предлагать фикс. Не гадать наугад.

### Фаза 5 — Ревью + верификация
- Ревьюеры ПАРАЛЛЕЛЬНО (одно сообщение), по зоне задачи (матрица ниже).
- Собери фидбек: жёсткие → средние → мелкие, докрути.
- Затем `/superpowers:verification-before-completion`. **«Готово» — только после неё.**

> **⛔ Reviewer Gate — ревью обязано быть субагентами, не самопроверкой.**
> Ценность ревьюера = **чистый контекст** (видит код незамыленным). Проверка «сам в этой же
> сессии» этого не даёт — это не ревью. Поэтому фаза закрывается только так:
> 1. Реально вызвал ревьюеров **через `Agent` tool** (`subagent_type: compound-engineering:review:*`),
>    в одном сообщении параллельно — минимум `correctness` + `maintainability`.
> 2. Свёл их фидбек и докрутил (жёсткие → средние → мелкие).
> 3. **Маркер закрытия** — прежде чем сказать «готово», в голове отметь:
>    `reviewers_spawned: [correctness, maintainability, …]` и `verification: passed`.
>    Хоть одно пусто (ревьюеров не спавнил / verify не гонял) → **«готово» запрещено**, вернись и закрой.
>
> Лень модели «докатить и проверить самому» — главный реальный риск этого трека. Не поддавайся:
> линейность экономит рой, но НЕ ревью. Единственное исключение — вес «тривиально» (ревью не нужно).

## Матрица ревью — кого звать (Фаза 5)

| Зона задачи | Ревьюер (`compound-engineering:review:*`) |
|-------------|-------------------------------------------|
| **ВСЕГДА** | `correctness-reviewer` + `maintainability-reviewer` |
| auth / публ.эндпоинты / ввод / права | `security-reviewer` |
| БД-запросы / циклы / кэш / тяжёлый I/O | `performance-reviewer` |
| retry / таймауты / фон-джобы / ошибки | `reliability-reviewer` |
| миграции / схема БД / бэкфилы | `data-migrations-reviewer` |
| API-роуты / типы / сигнатуры | `api-contract-reviewer` |
| стек TS / Python / Rails | `kieran-typescript-reviewer` / `kieran-python-reviewer` / `dhh-rails-reviewer` |
| слабые / отсутствующие тесты | `testing-reviewer` |
| **диф ≥50 строк ИЛИ деньги / auth / мутация данных** | **+ `adversarial-reviewer`** |

Зовутся параллельно через Agent tool (`subagent_type: compound-engineering:review:<persona>`)
или внутри Workflow через `agentType`.

## Правило экономии

Мелкая правка (одна строка, опечатка, текст, один файл <50 строк) — **просто Edit**, без фаз и
ревьюеров. Code cycle — для кода, который живёт дольше одного дня, и значимых артефактов.
Если в проектном `CLAUDE.md` уже описан цикл разработки — forge его исполняет, не дублирует.

## Когда код пишет рой, а не одна голова

Если Шаг 0 дал «рой» (масштаб/много углов), методология та же, но прошивается в агентов:
каждый кодер-агент в промпте начинает с `Skill: superpowers:test-driven-development`,
ревью — `agentType: compound-engineering:review:*`. См. `references/swarm.md`.
