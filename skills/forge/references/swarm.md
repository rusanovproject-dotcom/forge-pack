# Трек B — Рой агентов (ремесло дирижёра)

> Запускается, когда Шаг 0 forge дал вес «рой». Многоагентная оркестрация (инструмент **Workflow**) —
> только осознанно, не «накидал наугад».
>
> ⚠️ **Требует тул `Workflow`.** Он есть не во всех сборках/тарифах Claude Code. Если `Workflow`
> недоступен — Трек B не работает: не имитируй рой руками, вернись к Треку A (одна голова) или разбей
> задачу на несколько последовательных проходов. Проверь доступность до того, как обещать рой.

## Шаг 0 — А нужен ли рой вообще? (фильтр)

**СТОП перед запуском.** Рой = десятки агентов = жжёт токены. Оправдан только в 3 случаях:
1. **Объём не лезет в одну голову** — миграция, аудит всей кодбазы, разбор десятков файлов.
2. **Нужно много углов зрения разом** — ревью с 6 сторон, сравнение N подходов.
3. **Нужна уверенность через проверку** — найти → отдать находки скептикам опровергать → выжившие.

Ни один не подходит → **не запускай Workflow**: «тут хватит одной головы — делаю просто?»

## Шаг 1 — Классифицируй (5 типов)

| Тип | Когда | Скелет |
|-----|-------|--------|
| **understand** | разобраться в незнакомой системе/кодбазе | параллельные читатели по подсистемам → карта |
| **design** | выбрать подход к фиче/архитектуре | N попыток с разных углов → судьи → синтез из победителя |
| **review** | проверить код/документ/оффер | измерения → найти → адверсарно проверить каждую находку |
| **research** | собрать и проверить инфу из источников | мульти-модальный поиск → глубокое чтение → синтез с цитатами |
| **migrate** | массово переделать (рефактор/переименование) | найти места → трансформировать (worktree-изоляция) → проверить |

Не подошло — гибрид из паттернов ниже, объясни логику.

## Шаг 2 — Паттерн (4 кирпича)

- **pipeline (конвейер) — ПО УМОЛЧАНИЮ.** Каждый элемент идёт через все стадии сам, без барьера.
  Wall-clock = самая медленная одна цепочка, не сумма.
- **parallel (барьер)** — запустили всех, ЖДЁМ всех. Только при кросс-зависимости (дедуп общего
  списка, ранний выход если находок 0).
- **adversarial verify** — на каждую находку N скептиков ОПРОВЕРГНУТЬ (default «опровергнуто, если
  сомневаюсь»). Выживает пережившее ≥большинство. Страховка от красивых, но ложных выводов.
- **loop-until-dry** — раунды, пока 2 подряд не дадут нового. Ловит хвост, который «топ-10» теряет.

**Выбор:** сомневаешься pipeline vs parallel → бери pipeline. Барьер — только при кросс-зависимости.

## Шаг 3 — Уточняющие вопросы (только если без них никак)

Живым текстом, НЕ попапом. Максимум 3, лишь то, что меняет конструкцию роя:
1. **Глубина** — «быстро» или «люто» (большой пул, 3-5 скептиков, синтез)? Если партнёр
   просит «максимально тщательно / ничего не упусти» — это всегда «люто».
2. **Масштаб** — сколько целей/файлов/источников (определяет fan-out).
3. **Стоп-критерий** — фиксированный объём или loop-until-dry.

Всё ясно из задачи → не спрашивай, показывай план.

## Шаг 4 — План роя ПЕРЕД запуском (обязательно)

```
План роя:
• Тип: review · Паттерн: pipeline + adversarial verify
• Фаза 1 (Найти): 6 агентов по измерениям параллельно
• Фаза 2 (Проверить): на каждую находку 3 скептика
• Масштаб: ~25-40 агентов · время: ~10-20 мин стены · съест заметную долю сессионного лимита
• Прогресс: /workflows (можно оборвать в любой момент)
```
Ждёшь «го». Партнёр может урезать глубину/охват прямо тут.

> **Дай честную прикидку цены, не плейсхолдер.** Прикинь число агентов (сумма по фазам) и переведи
> в понятное: сколько примерно минут стены и что это ощутимая доля дневного лимита. Кап — **16
> одновременно / 1000 за прогон** (Шаг 7). Десятки агентов на большой кодбазе выжигают 5-часовой
> лимит за ~15-20 минут, и токены не возвращаются — поэтому «го» должно быть осознанным, особенно
> если человек ещё не гонял рои. Не уверен в масштабе — начни с узкого среза (Шаг 6, правило 4).

## Шаг 5 — Запусти и держи в цикле

- Через инструмент **Workflow** (детерминированный скрипт: agent/parallel/pipeline/phase/log).
- **Один Workflow = одна фаза-веер.** Не строй монстра. Несколько подряд > один гигант.
- `meta` с phases, `schema` где нужна чистая дата, `.filter(Boolean)` после parallel.
- **Не молчи про обрезку охвата** — через `log()` и в финальном отчёте.

## Шаг 6 — Правила мастерства

1. **🥇 Не давай LLM то, что делает код.** Линтер, типы, тесты, дедуп, reduce (`flatMap`/`filter`/`Set`)
   — обычным JS. Агенту — только суждения: безопасность, логика, контракты, архитектура, смысл.
2. **Дешёвая модель на разведку, дорогая на суждение.** Чтение/exploration → `model:'haiku'`;
   верификация/синтез → opus/sonnet. Пер-стадийный `model` в `agent()`.
3. **`schema` на каждом агенте**, чей результат идёт дальше — валидный JSON с авто-ретраем.
4. **Сначала узкий срез, потом масштаб.** Незнакомый рой → прогон на одной папке → глянул
   `/workflows` → расширил.
5. **loop-until-dry дедупит против ВСЕГО виденного**, не только подтверждённого — иначе не сходится.
6. **Корректность > скорости.** Уверенность даёт паттерн проверки (adversarial/diverse-lens),
   а не число агентов.

## Шаг 7 — Страховка от runaway (главный реальный риск)

Degenerate loop выжигает 5-часовой лимит за ~18 минут, токены не возвращают:
- Незнакомый/самописный рой → держи `/workflows` открытым на старте, залип → `x` (стоп).
- **Читай сгенерённый скрипт глазами** перед дорогим прогоном (`/workflows` → View raw script).
- Кап: **до 16 одновременно, до 1000 за прогон**. План на сотни веером → передробить.

## Грабли рантайма

- **Вложенность одна:** агент роя НЕ спавнит суб-суб-агента. **НО Skill tool ему доступен** —
  ✅ проверено 2026-06-27: top-level Workflow-агент видит Skill+ToolSearch и грузит скиллы.
  (Прошлая заметка «рой не видит Skill» — устарела.) Значит: под-рой из агента — нельзя,
  а вызвать скилл (методологию) — можно и нужно. Вся веерная оркестрация — на верхнем уровне скрипта.
- **Недетерминизм роняет прогон:** `Date.now()`/`Math.random()`/`new Date()` без аргументов → ошибка
  (журнал для resume). Время/случайность — через `args`.
- **Нет ввода человека посреди прогона** — контроль между стадиями → дроби на отдельные workflow.
- **Слепота к соседним файлам:** агент-ревьюер видит только данное ему. Давай контекст явно в промпт.
- **Параметры запуска иногда молча теряются** — логируй `args` первой строкой через `log()`.

## Принципы внутрь агентов роя (по РОЛИ, не «всем TDD»)

Чтобы рой был не тупой — прошивай принцип под роль агента, а не валом:
- **пишет код** (migrate, code-фаза) → в промпт первой строкой:
  *«Сначала Skill: superpowers:test-driven-development и следуй; затем — задача…»*
- **ревьюер** → `agentType: 'compound-engineering:review:<persona>'`.
- **understand / research / design** (не пишет код) → **никакого TDD** (для них это мусор и жжёт
  контекст) — дай чёткую рубрику задачи в промпт.

Следование проверяй маркером в `schema` (напр. `tdd_done: "red→green"`), не презумпцией:
что агент РЕАЛЬНО прошёл цикл — держи полем, пусто → реджект. (Skill он грузит — см. заметку в Шаге 0 выше.)
