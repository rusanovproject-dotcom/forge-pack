# Forge — Кузница: единый цикл разработки для Claude Code

**Что это.** Один скилл-оркестратор, через который проходит любая задача по коду. Вместо
«накидал кода наугад» Forge ведёт работу по осознанному циклу: **классифицирует вес задачи →
план → чистый код через TDD → ревью отдельными агентами → верификация**. Сам решает, *насколько
глубоко* копать: тривиальную правку не раздувает, крупную фичу гонит по полному циклу, а объёмную
работу раскидывает роем агентов.

Forge — **дирижёр, а не движок**. Он не переизобретает методологию, а связывает две проверенные
библиотеки (ставятся отдельно, см. ниже):

- **Superpowers** — процесс: TDD, систематический дебаг, верификация перед «готово».
- **Compound Engineering** — план и ревью: планировщик + ~15 персон-ревьюеров (correctness,
  security, performance, тесты, и т.д.), каждый со своим чистым контекстом.

Идея Forge: **ревью — это не самопроверка**. «Готово» разрешено только после того, как код
реально прошёл через отдельных ревьюеров-субагентов и верификацию, а не после «ну вроде норм».

---

## ⚡ Быстрый старт

```bash
git clone https://github.com/rusanovproject-dotcom/forge-pack.git
cd forge-pack
./install.sh                 # поставит скилл в ~/.claude/skills/forge и проверит зависимости
```

`install.sh` скопирует скилл и скажет, каких плагинов не хватает. Дальше — **2 ручных шага**
(плагины ставятся изнутри Claude Code, скрипт это сделать не может).

---

## Зависимости (обязательно — без них Forge пустой)

Forge зовёт скиллы двух плагинов по имени. Нет плагина → вызовы ссылаются в пустоту.
Поставь оба **внутри Claude Code** (не в терминале):

```
/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

/plugin marketplace add EveryInc/compound-engineering-plugin
/plugin install compound-engineering@compound-engineering-plugin
```

Проверить, что встали: `/plugin` → оба в списке enabled. Минимальные версии, на которых
собран Forge: **superpowers ≥ 5.1**, **compound-engineering ≥ 2.65**. Если апстрим переименует
персону-ревьюера в мажорной версии — некоторые имена в матрице ревью могут разойтись; тогда
сверься со списком субагентов своего плагина.

> **Трек B (рой агентов)** дополнительно требует инструмент `Workflow` — он есть не во всех
> сборках Claude Code. Нет `Workflow` → Треки A (одна голова) и C (loop) работают, рой — нет.
> Forge это понимает и не будет имитировать рой руками.

## Как подвязать (чтобы Claude сам заходил через Forge)

Скилл активируется двумя способами:

1. **Явно:** `/forge собери фичу X` — или триггер-словами: «напиши код», «построй сервис»,
   «реализуй», «прогони по циклу», «запусти рой», «оркестрируй».
2. **Автоматически** — если пропишешь роутинг в свой `CLAUDE.md`. Вставь этот блок:

```markdown
## Разработка → через Forge

Любая задача по коду (фича, сервис, фронт/бэкенд, фикс, миграция) и любая многоагентная
оркестрация идут через скилл `/forge`, а не «накидал кода руками». Forge сам определит вес:
тривиальная правка → просто Edit без цикла; фича → код-цикл (TDD + ревью); объём/много углов →
рой агентов; итерация под критерий → автономный loop.

НЕ через forge: «позови [агента]» (один субагент), ответ на вопрос, правка одной строки/текста.
```

После этого на фразу «сделай фичу» Claude сам вспомнит про Forge и зайдёт через цикл.

## Под какие задачи (и когда НЕ надо)

| Задача | Что сделает Forge |
|--------|-------------------|
| «поправь опечатку / переименуй» | ничего лишнего — просто Edit, без цикла (вес «тривиально») |
| «сделай вот эту фичу» | код-цикл: recon стека → TDD → correctness+maintainability ревью → верификация |
| «крупная незнакомая подсистема» | + план (ce-plan) и document-review перед кодом |
| «трогает auth / деньги / данные» | risk-override: обязательный security-ревьюер (+ adversarial) |
| «разбери/переделай весь проект», «сравни 5 подходов» | рой агентов (Трек B), с планом и ценой перед запуском |
| «крути, пока метрика не сойдётся» | автономный loop (Трек C, на нативном `/goal`) |

**Не для Forge:** обычный вопрос-ответ, вызов одного конкретного субагента, правка одной строки.
Для них Forge сам скажет «тут цикл не нужен» и не будет разводить процесс.

## Что внутри пака

```
forge-pack/
├── README.md               # этот файл
├── install.sh              # установка + проверка зависимостей
└── skills/forge/
    ├── SKILL.md            # мозг: Шаг −1 preflight → Шаг 0 классификатор → Треки A/B/C
    └── references/
        ├── code-cycle.md   # Трек A — код-цикл (TDD + матрица ревью)
        └── swarm.md        # Трек B — рой агентов (паттерны, страховка от runaway)
```

> Пак чист по ПД — никаких личных данных, токенов, приватных путей. Трек C (автономный loop)
> в этой версии упрощён до нативного `/goal`, чтобы не тащить лишние зависимости.

## Установка вручную (если не хочешь скрипт)

```bash
cp -r skills/forge ~/.claude/skills/forge
```

Затем поставь два плагина (раздел «Зависимости» выше) и по желанию впиши блок роутинга в `CLAUDE.md`.
Перезапусти Claude Code — готово.

## Как это работает (одним взглядом)

```
любая задача по коду
        │
   Шаг −1: живы ли плагины/тулы?  ── нет → честно скажи, что поставить
        │
   Шаг 0: какой ВЕС?
        ├─ тривиально ───────────→ просто Edit. Стоп.
        ├─ одна голова ──────────→ Трек A: TDD → ревью → верификация
        ├─ крупная фича ─────────→ Трек A полный: + план + document-review
        ├─ рой ──────────────────→ Трек B: Workflow, план+цена → «го» → веер агентов
        └─ автономный loop ──────→ Трек C: /goal крутит до критерия
```

Партнёр всё время в цикле: видит план, видит цену роя до запуска, говорит «готово» только после
реальной верификации. Кузница куёт — партитуру читает человек.
